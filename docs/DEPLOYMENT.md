The workflow does not specify the last five numerical inputs, an allocation split or the factory's source. These are explicit provisional parameters held in `test/helpers/LaunchParameters.sol`. No `launch.json` is generated by this source assignment. The independently reviewed manifest must match the final deployment inputs, and the launch rehearsal must be rerun if price, allocation or range changes. This local factory models the stated lifecycle; it is not evidence of equivalence with unavailable factory code.

The rehearsal factory deploys ONEW into its own balance, mines and deploys the hook, initializes the pool, computes liquidity using `getLiquidityForAmount1`, and creates a position owned by the factory in a PoolManager unlock. At the chosen starting price the position is wholly ONEW. It transfers only ONEW using `sync -> transfer -> settle`, leaving at most 1,000 token base units of rounding dust and zero manager ETH. The first downward buy crosses the small gap to the upper tick and activates liquidity. Tests verify the initial price, actual position, zero native balance, actual buyer debit, tokens received, subsequent sell taxation and subsequent claim-funded bonus.

The deployment service must mine the CREATE2 salt using the **actual factory address** and the complete init code (`creationCode ++ abi.encode(manager)`). The tested helper illustrates this calculation; its local salts are not deployment salts. Require `(uint160(predictedAddress) & 0x3fff) == 0x00cc` and an unused address, then deploy exactly the reviewed code and constructor argument. Changing compiler settings, manager or deploying factory changes the mined address. Constructor validation cannot be bypassed in the test helper.

Services own source publication, signed artifact linkage, policy, attestation, admission, final manifest validation and authorized deployment, followed by the frontend. Policy and signature linkage are not contract setters. Reviewers should treat concrete bytecode, constructor, source, policy or authorization mismatches as findings. This assignment submits no transaction and does not control any funded wallet.

The independent review should cover negative specified-delta settlement, exact-output ETH-leg semantics, overflow boundaries, partial-fill rollback, per-pool isolation, multi-swap transient-slot reuse, dust, donated-claim surplus and attempts to withdraw more than a pot. The test suite is local verification, not that independent review.

After deployment, services should publish the token, hook, pool ID, complete pool key, factory transaction and router address, verify runtime/ABI correspondence and confirm initialization and position inputs. Monitor `SellTaxed` and `BuyBonus` against per-pool pot changes and aggregate ETH claims. No operator can change rates or recover pot funds. If no later buys occur, tax claims remain in the pot. Router slippage protection and authenticating the displayed deployment belong to the frontend/integration service.
